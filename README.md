# MultiElma

Android-клиент для работы с несколькими учётными записями self-hosted портала ELMA365 одновременно: несколько аккаунтов одного портала, параллельная работа с задачами, сервисными коллекциями, лентой и документооборотом.

## Возможности

### Мульти-аккаунт
- Одновременная работа с несколькими учётными записями одного ELMA-портала
- Дедупликация задач по ключу `baseUrl::taskId` (одна задача не дублируется, если видна из разных аккаунтов)
- Выбор активного аккаунта через чип-селектор; режим «Все» для просмотра данных со всех аккаунтов
- Автоматическое присвоение цвета каждому аккаунту

### Задачи
- Список задач с фильтрами: все / активные / просроченные / завершённые, поиск
- Детальная карточка задачи: статус, приоритет, автор, дата создания, срок, описание
- Действия над задачами: «Принять» и «Завершить» (через exits ELMA)
- Подзадачи процесса (items-linked)

### Сервис (customer_service)
- 27 коллекций: клиенты, договоры, заявки, визиты, статьи, новости, исполнители и др.
- Пагинация и серверный поиск для больших справочников (клиенты ~3.8M, договоры ~874K и т.д.)
- Детальная карточка элемента с дополнительными полями и вложениями
- Статусы ЭЦП (Picasso) для документов с файлами

### Лента
- Каналы и сообщения ленты, счётчик непрочитанных
- Бесконечная прокрутка, pull-to-refresh

### Поддержка ролей
- `userKind=portal` (мастер) и `userKind=default` (работник магазина)
- Разделы без доступа скрываются из навигации (проверка `isHaveAccess`)

### Ещё разделы
- **Согласования (Docflow):** список документов на согласовании и ознакомлении (по требованию, без поллинга)
- **Категории обращений:** иерархическое дерево (appeals directories)
- **Рабочий календарь:** месяц с расписанием по 7-дневному циклу, особыми днями и карточкой дня
- **Уведомления:** запрос `POST_NOTIFICATIONS` (Android 13+), уведомления о новых задачах и смене статусов
- **Фоновое обновление:** foreground-сервис (`KeepAlive`), удержание экрана, realtime-подписки и синхронизация

## Установка и запуск

```bash
npm install
npm start          # Metro bundler
npm run android    # сборка и запуск на устройстве/эмуляторе
```

### Сборка release APK

```bash
cd android
JAVA_HOME="путь/к/jdk-17" ./gradlew assembleRelease
```

Результат: `android/app/build/outputs/apk/release/app-release.apk` (JS-бандл вшит, Metro не требуется).

Для подписи release задайте переменные окружения `MULTIELMA_STORE_FILE`, `MULTIELMA_STORE_PASSWORD`, `MULTIELMA_KEY_ALIAS`, `MULTIELMA_KEY_PASSWORD`. Без них APK собирается с debug-подписью.

## Структура проекта

```
src/
├── screens/          # Экраны: auth / tasks / customer / feed
├── components/       # Переиспользуемые UI-компоненты
├── domain/           # Доменные сервисы и чистая логика (TaskService, SyncScheduler, visit, ...)
├── services/         # Оркестрация: синхронизация, realtime, планировщики
├── infrastructure/   # Транспорт, кэш, сессии, HTTP-ошибки
│   └── api/          # API-модули портала (auth, tasks, collections, accept, visit, ...)
├── store/            # Zustand-сторы (auth, tasks, feed, customer-service, settings)
├── hooks/            # Пользовательские хуки
├── native/           # Мост к нативным модулям (KeepAlive)
├── config/           # Константы (интервалы, лимиты, ELMA-константы)
├── interfaces/       # Порты (интерфейсы персистентности)
├── types/            # TypeScript-типы
├── utils/            # Утилиты
├── theme/            # Тема и цвета
└── diag/             # Диагностические логи
```

`src/services/elma-api.ts` — баррель, реэкспортирующий публичный API из `src/infrastructure/api/*` (импортёры продолжают использовать единый путь).

## Архитектура

- **Слои:** `screens`/`hooks` (presentation) → `domain`/`services` → `infrastructure` (транспорт, API). Домен не зависит от zustand-сторов напрямую, а работает через порты (`interfaces/persistence`).
- **Мульти-аккаунт:** данные ключуются по `accountId`. При добавлении аккаунта проверяется дублирование по `baseUrl + email`.
- **Дедупликация:** задачи и уведомления дедуплицируются по `baseUrl::taskId`.
- **Кэш:** TTL-кэш в памяти с привязкой к аккаунту.
- **Синхронизация:** фоновый планировщик с адаптивными интервалами и джиттером, ограничением параллельности и защитой от лишних запросов к серверу.

## Замечания по эксплуатации

- **Бережный режим к серверу:** интервалы опроса 15–120 с (по умолчанию 30 с) со случайным джиттером; запросы к одному хосту сериализуются с минимальным интервалом.
- **Уведомления** требуют разрешения `POST_NOTIFICATIONS` (Android 13+); при отказе уведомления не работают.
- **Keep-alive** (удержание экрана / foreground-сервис) управляется в настройках; используется `START_STICKY` и partial wake lock.
- **Оптимизация аккумулятора:** приложение может запросить её отключение для корректной фоновой работы (важно на устройствах с агрессивным менеджментом батареи).
